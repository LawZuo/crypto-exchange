# Crypto Exchange 项目文档

## 1. 项目简介

`crypto-exchange` 是一个基于 Spring Boot 与 Spring Cloud 的加密货币交易平台后端项目。系统采用 Maven 多模块和微服务架构，当前实现了统一网关、用户端聚合接口、管理端聚合接口、认证、用户、账户、行情数据和资源服务等基础能力。

当前项目更接近交易所后端基础框架：用户、账户和行情链路已经建立，但撮合、订单、资产清结算、风控等完整交易能力尚未实现。

## 2. 技术栈

| 分类 | 技术 |
|---|---|
| 开发语言 | Java 17 |
| 基础框架 | Spring Boot 3.2.9 |
| 微服务 | Spring Cloud 2023.0.3 |
| 服务治理 | Spring Cloud Alibaba、Nacos |
| 服务调用 | OpenFeign、Spring Cloud LoadBalancer |
| 网关 | Spring Cloud Gateway |
| 数据访问 | MyBatis-Plus、dynamic-datasource、Druid |
| 数据库 | MySQL 8 |
| 缓存 | Redis |
| 消息队列 | RabbitMQ |
| 数据迁移 | Flyway |
| API 文档 | Springdoc OpenAPI / Swagger UI |
| 行情来源 | Binance REST API / WebSocket |
| 构建部署 | Maven、Docker、Docker Compose |

## 5. 已有业务能力

- 用户注册、登录、退出及 Redis Token 会话。
- 网关统一鉴权及用户身份请求头透传。
- 用户信息、钱包信息查询。
- KYC 申请的创建、更新、删除、查询和状态更新。
- Binance Ticker、Depth、Trade、Kline 行情获取。
- 行情 Redis/内存缓存及 WebSocket 推送。
- 头像和 KYC 图片上传。
- 邮箱验证码异步发送。
- Web 和 Admin 两类外部聚合接口。
- 统一响应、异常处理、日志、接口幂等和 OpenAPI 文档。

## 6. 外部访问入口

生产或联调时只建议暴露网关：

```text
Web API:   http://<host>:18080/api/crypto-exchange/web/**
Admin API: http://<host>:18080/api/crypto-exchange/admin/**
Swagger:   http://<host>:18080/swagger-ui.html
```

统一响应格式：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

需要鉴权的请求使用：

```http
Authorization: Bearer <token>
```

## 7. 本地开发

### 环境要求

- JDK 17
- Maven 3.9+
- MySQL 8.x
- Redis
- RabbitMQ
- Nacos 2.x

### 构建

```bash
mvn -f exchange-parent/pom.xml clean package -DskipTests
```

### 推荐启动顺序

1. Nacos、MySQL、Redis、RabbitMQ。
2. `exchange-service-datasource`、`exchange-service-resource`。
3. `exchange-business-user`、`exchange-business-account`、`exchange-business-market`。
4. `exchange-service-auth`。
5. `exchange-web`、`exchange-admin`。
6. `exchange-gateway`。

## 8. 当前边界与注意事项

- Admin 端目前只有用户、钱包和交易对三个只读查询接口，尚无独立管理员登录和 RBAC 权限模型。
- 网关当前对 Web 登录、注册、行情和 API 文档放行；其他 Web/Admin 路径默认要求 Token。
- 行情 WebSocket 由 Gateway 的 `/ws/market` 统一转发到 market 服务，前端不直连 market 端口。
- 多个服务配置仍含固定的 Nacos 地址或开发默认凭据，生产部署前必须迁移为环境变量或 Nacos 密文配置。
- `.env.example` 当前包含示例地址和口令，不能直接当作安全的生产配置使用。
- 项目尚未实现完整的订单、撮合、成交、资金清算和风控链路。
