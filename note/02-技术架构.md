# Crypto Exchange 技术架构

## 1. 架构概览

系统采用“统一网关 + 接口聚合层 + 领域服务 + 通用服务 + 基础设施”的分层微服务架构。

```text
Browser / App / Admin
          |
          v
 exchange-gateway :18080
   |            |
   v            v
exchange-web   exchange-admin
   |                |
   +------- OpenFeign / Nacos -------+
                    |
      +-------------+--------------+
      |             |              |
      v             v              v
    auth      business-user  business-account
      |                             
      +-----------> business-market
                         |
            +------------+-------------+
            v                          v
  module-datasource             module-resource
            |                          |
         Binance                  Upload / Mail

Infrastructure: Nacos / MySQL / Redis / RabbitMQ
```

## 2. 分层职责

### 接入层

`exchange-gateway` 是系统唯一推荐的外部入口，负责：

- 按 URL 前缀将请求转发到 Web 或 Admin 聚合服务。
- 从 `Authorization` 读取 JWT。
- 校验 JWT 并确认 Redis 登录 Token 仍有效。
- 向下游传递用户 ID、用户名和 Token。
- 聚合 Web/Admin OpenAPI 文档。
- 提供全局 CORS 配置。

路由规则：

| 外部路径 | 目标服务 | 转发后路径 |
|---|---|---|
| `/api/crypto-exchange/web/**` | `exchange-web` | 去除前三段前缀 |
| `/api/crypto-exchange/admin/**` | `exchange-admin` | 去除前三段前缀 |

### BFF 聚合层

- `exchange-web`：面向普通用户，组合认证、用户、账户、行情和资源接口。
- `exchange-admin`：面向运营管理端，目前只提供跨服务只读查询。

BFF 不直接访问数据库，通过 `exchange-api-*` 中定义的 OpenFeign 契约调用领域服务。

### 领域服务层

- `exchange-service-auth`：认证编排、密码验证、JWT 签发、Redis 会话管理。
- `exchange-business-user`：用户资料、注册落库、登录记录、KYC。
- `exchange-business-account`：钱包、充值记录、提现记录。
- `exchange-business-market`：交易对配置、行情 REST 查询、缓存消费与 WebSocket 发布。

### 通用业务服务层

- `exchange-service-datasource`：连接 Binance REST/WebSocket，标准化行情并发布到 RabbitMQ/Redis。
- `exchange-service-resource`：组合图片上传与邮件发送能力。

### 公共能力层

`exchange-common-*` 提供统一响应、异常处理、安全上下文、Redis、RabbitMQ、接口文档和 Web 自动配置。`exchange-api-*` 提供跨服务接口契约、DTO、VO 与 Feign fallback。

## 3. 核心调用链

### 登录链路

```text
Client
 -> Gateway（登录路径放行）
 -> WebAuthController
 -> AuthController
 -> User Service（查询用户并记录登录）
 -> Auth Service（生成 JWT，Token 写入 Redis）
 -> Client
```

登录后的请求由网关校验 JWT 和 Redis Token，再把身份信息透传给下游。

### 用户与钱包查询

```text
Client -> Gateway -> exchange-web/admin
  -> RemoteUserService -> business-user -> MySQL
  -> RemoteAccountService -> business-account -> MySQL
```

### 行情链路

```text
Binance REST/WebSocket
 -> exchange-service-datasource
 -> Redis / RabbitMQ
 -> exchange-business-market
 -> REST Cache API / WebSocket Publisher
 -> exchange-web -> Gateway -> Client
```

历史行情和快照可经 datasource REST 获取，实时流通过 RabbitMQ 解耦采集与业务消费。

### 邮件与上传链路

```text
Client -> Gateway -> exchange-web
 -> exchange-service-resource
 -> Upload Service / RabbitMQ Email Queue
```

## 4. 数据与中间件

| 组件 | 用途 |
|---|---|
| Nacos | 服务注册发现、配置中心 |
| MySQL | 用户、账户、交易对等持久化数据 |
| Redis | 登录 Token、幂等键、行情快照与缓存 |
| RabbitMQ | 行情数据和邮件任务异步传输 |
| Binance | 外部行情数据源 |

业务服务通过 Flyway 的 `db/migration` 脚本初始化用户和行情库结构。

## 5. 安全架构

- 客户端使用 `Authorization: Bearer <token>`。
- 网关解析 JWT，并检查 Redis 中 `login:token:*` 会话键。
- 网关忽略路径包括 Web 登录、注册、行情接口及 OpenAPI 文档。
- 下游服务通过内部请求头读取用户身份。
- 公共安全模块提供接口幂等拦截能力。

当前限制：Admin 接口仅复用普通 Token 校验，没有管理员身份、角色、权限点和审计体系，不应直接作为正式后台权限方案。

## 6. 配置架构

配置来源分为三层：

1. 各模块 `application.yml` 和 `application-*.yml`。
2. Docker Compose 注入的环境变量。
3. Nacos 中的共享及服务级配置。

主要 Nacos 配置名包括：

```text
exchange-config-database.yml / CONFIG_GROUP
exchange-config-redis.yml    / CONFIG_GROUP
exchange-config-rabbitmq.yml / CONFIG_GROUP
exchange-business-market.yml / BUSINESS_GROUP
exchange-web.yml             / WEB_GROUP
exchange-admin.yml           / ADMIN_GROUP
```

## 7. Maven 模块关系

根 `pom.xml` 聚合 `exchange-parent`，`exchange-parent` 统一版本和插件并继续聚合一级模块；各一级聚合模块再管理其子模块。构建完整 reactor 时使用：

```bash
mvn -f exchange-parent/pom.xml clean verify
```

## 8. 可演进方向

- 增加订单、撮合、成交、账本、清结算和风控领域。
- 为 Admin 增加独立认证、RBAC、操作审计和敏感操作二次确认。
- 将硬编码地址和凭据全部外置，并引入密钥管理。
- 增加网关限流、熔断、链路追踪和指标监控。
- 为市场 WebSocket 增加网关路由、连接鉴权和订阅限额。
- 对账户资金变更使用业务流水号、数据库唯一约束和不可变账本。
