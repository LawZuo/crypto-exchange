# Crypto Exchange 部署说明

## 1. 部署方式

项目提供 Docker Compose 发布方式：本地使用 Maven 打包并生成发布目录，上传服务器后构建镜像并启动九个服务。默认只向宿主机暴露网关端口 `18080`。

## 2. 环境要求

### 本地打包环境

- JDK 17
- Maven 3.9+
- Bash

### 服务器环境

- Linux x86_64/arm64（需匹配基础镜像）
- Docker Engine
- Docker Compose v2
- 可访问 Nacos 2.x、MySQL 8、Redis、RabbitMQ
- 建议至少 4 核 CPU、8 GB 内存；实际容量应通过压测确定

### 外部基础设施

部署前准备：

- Nacos 命名空间和服务配置。
- 用户库、账户库、行情库及对应数据库账号。
- Redis 实例。
- RabbitMQ 实例、交换机/队列配置权限。
- 邮件 SMTP 凭据。
- 文件上传持久化目录或对象存储。

## 3. Nacos 配置

至少准备以下配置：

| Data ID | Group | 主要内容 |
|---|---|---|
| `exchange-config-database.yml` | `CONFIG_GROUP` | MySQL 用户、密码及各业务库 URL |
| `exchange-config-redis.yml` | `CONFIG_GROUP` | Redis 主机、端口、密码、DB |
| `exchange-config-rabbitmq.yml` | `CONFIG_GROUP` | RabbitMQ 主机、端口、账号、队列 |
| `exchange-business-market.yml` | `BUSINESS_GROUP` | 行情缓存和 WebSocket 参数 |
| `exchange-web.yml` | `WEB_GROUP` | Web 服务扩展配置，可为空 |
| `exchange-admin.yml` | `ADMIN_GROUP` | Admin 服务扩展配置，可为空 |

配置键需与源码占位符一致，例如数据库配置使用：

```yaml
MYSQL:
  DB_USER: exchange
  DB_PASSWORD: change-me
  USER:
    DB_URL: jdbc:mysql://mysql:3306/exchange_user
  ACCOUNT:
    DB_URL: jdbc:mysql://mysql:3306/exchange_account
  MARKET:
    DB_URL: jdbc:mysql://mysql:3306/exchange_market
```

Redis/RabbitMQ 的具体键名以各模块 `application-redis.yml`、`application-mq.yml` 为准。

## 4. 本地生成发布包

在项目根目录执行：

```bash
chmod +x docker-package.sh
./docker-package.sh
```

脚本会：

1. 执行 Maven `clean package`，跳过测试。
2. 收集九个 Spring Boot JAR。
3. 复制 Dockerfile、Compose、环境变量模板和部署脚本。
4. 生成 `dist/crypto-exchange-docker/`。

已有最新 JAR 时可使用：

```bash
./docker-package.sh --skip-build
```

离线构建可使用：

```bash
MAVEN_OFFLINE=true ./docker-package.sh
```

## 5. 上传服务器

```bash
rsync -avP dist/crypto-exchange-docker/ \
  deploy@<server>:/opt/crypto-exchange-docker/
```

登录服务器：

```bash
cd /opt/crypto-exchange-docker
chmod +x deploy.sh
```

## 6. 配置环境变量

首次运行会从 `.env.example` 创建 `.env` 并停止：

```bash
./deploy.sh up
```

编辑 `.env`：

```dotenv
IMAGE_TAG=latest
GATEWAY_HOST_PORT=18080
TZ=Asia/Shanghai

NACOS_SERVER_ADDR=<nacos-host>:8848
NACOS_NAMESPACE=<namespace-id>
NACOS_USERNAME=<username>
NACOS_PASSWORD=<strong-password>

REDIS_HOST=<redis-host>
REDIS_PORT=6379
REDIS_PASSWORD=<strong-password>
REDIS_DATABASE=0
REDIS_TIMEOUT=5000ms

BT_DATASOURCE_BASE_URL=http://exchange-datasource:18461

JAVA_OPTS=-XX:+UseContainerSupport -XX:MaxRAMPercentage=75.0
```

安全要求：

- 必须替换仓库示例中的所有地址和口令。
- `.env` 不得提交到 Git，也不要通过聊天或工单明文传播。
- SMTP、MySQL、RabbitMQ 等凭据应放入 Nacos 安全配置或密钥管理系统。
- 防火墙只开放网关端口；数据库和中间件应限制来源网络。

## 7. 启动与管理

```bash
./deploy.sh up
./deploy.sh ps
./deploy.sh logs
./deploy.sh restart
./deploy.sh down
```

`up` 会校验 Compose、构建镜像并后台启动服务。上传文件保存在 Docker volume `exchange-uploads`，日志写入发布目录 `logs/<service>/`。

## 8. 验证部署

查看容器状态：

```bash
docker compose ps
```

查看网关日志：

```bash
docker compose logs --tail=200 exchange-gateway
```

验证公开行情接口：

```bash
curl "http://<server>:18080/api/crypto-exchange/web/market/symbols"
```

验证 Swagger：

```text
http://<server>:18080/swagger-ui.html
```

服务启动后还应在 Nacos 控制台确认九个服务实例注册正常。

## 9. 网络与端口

| 端口 | 用途 | 是否建议公网开放 |
|---:|---|---|
| 18080 | 网关 | 是，建议经 HTTPS 反向代理 |
| 18300-18472 | 内部微服务 | 否 |
| 8848 及 Nacos gRPC 端口 | Nacos | 否 |
| 3306 | MySQL | 否 |
| 6379 | Redis | 否 |
| 5672/15672 | RabbitMQ/管理台 | 否 |

生产环境建议使用 Nginx/负载均衡器终止 TLS，并将流量代理到 `18080`。

## 10. 更新与回滚

更新：

```bash
./docker-package.sh
rsync -avP dist/crypto-exchange-docker/ deploy@<server>:/opt/crypto-exchange-docker/
ssh deploy@<server> 'cd /opt/crypto-exchange-docker && ./deploy.sh up'
```

当前脚本会在服务器重新构建镜像。正式环境建议使用唯一 `IMAGE_TAG` 并保留上一版本镜像；回滚时恢复上一版发布目录或镜像标签，再执行 `docker compose up -d`。

## 11. 常见问题

- 服务无法注册：检查 Nacos 地址、命名空间、账号及 Nacos 2.x gRPC 端口。
- Feign 503：确认目标服务在同一命名空间注册，服务名与配置一致。
- 数据库启动失败：检查 Nacos 数据库配置和 Flyway 权限。
- Token 校验失败：确认网关和认证服务连接同一 Redis DB。
- 行情为空：检查服务器访问 Binance 的网络、RabbitMQ 队列和 market 消费日志。
- 上传后文件丢失：确认 `exchange-uploads` volume 未删除，执行 `down` 时不要附加 `-v`。
